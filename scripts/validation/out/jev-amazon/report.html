What this run changes

Only the explore-loop planner is Jev. mr_plan, explore_verify, observe, and fill still go through minimax/minimax-m3. Jev does not see screenshots. Rationales are assembled from inventory names rather than generated prose. Fill still needs an LLM because Jev cannot invent search strings.

The baseline ran on 9 July 2026. Amazon.es has almost certainly shifted since then, so a family that fails here is not automatically a planner regression. Treat outcome flips as leads, not proof. Cost and latency on plan_explore are the cleaner comparison because those calls are the thing we swapped.

How to read this

If Jev is doing its job, plan_explore latency should collapse from seconds to hundreds of milliseconds, token volume on those calls should drop, and compiled families should not get worse in an obvious way. Verify still dominates wall clock because it is vision plus Minimax. A cheaper planner that still waits on verify will not look like a 12 minute job turning into a 1 minute job.
